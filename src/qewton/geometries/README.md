# Geometries Submodule

The `geometries` module defines the domains of physical space used in the algorithms. They live inside spaces which are defined via `Variable` objects. For example, a 2D image domain could be defined by a `Geometry` with variables 'x' and 'y', while a time series would have a variable 't', with an interval as the domain.

We integrate some simple own domains, and refer to CAD and meshing libraries for more complex stuff. Here we also enable marking specific regions of the domain or its boundary, which is useful for applying boundary conditions in physics-informed models. The geometries are also used to generate collocation points for training PINNs, and to provide spatial context (e.g., normal vectors) to nodes during the forward pass.

## Key Components
- **`Geometry`**: The base class for defining a domain (e.g., a Hypercube, Circle, or complex Mesh).
- **`DiscreteGeometry`**: A geometry defined by a fixed set of points, useful for graph-based models or when working with pre-sampled data, or everything lying on a grid. A `MeshGeometry` is a specific type of `DiscreteGeometry` can also be generated by meshing other `Geometry` objects.
- **`BoundaryGeometry`**: A `Geometry` that represents the boundary of another geometry. It can provide additional information such as normal vectors or boundary masks.
- **`ProductGeometry`**: The Cartesian product of two geometries, created with `geometry_a * geometry_b` (e.g. space x time). Meshing it meshes every factor and returns a `ProductMeshGeometry`, whose vertices are all combinations of the factor vertices (first factor varying slowest) and whose simplex mesh is built on demand. `ProductDiscreteGeometry` is the product of plain discrete point sets that keeps each factor's own shape, e.g. for reference data on a grid.
- **`SampledGeometry`**: Created by every `PointSampler`; holds the points (and cells) of the sampler's current forward pass and a reference to the source geometry, so data configurations and plots can refer to the sampled points.

## Goals
1. **Abstraction**: Decouple the physical definition of a problem (boundaries, dimensions) from the tensor operations.
2. **Sampling**: Provide standardized methods to sample points for training, such as collocation points for Physics-Informed Neural Networks (PINNs).
